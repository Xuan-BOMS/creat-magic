# 轰界法术生成器实施方案

## 1. 当前结论

项目已经进入可运行 MVP：后端规则内核、JSON 节点库、四个示例、前端工作台和基础验证均已完成。

MVP 不再追求一次性覆盖所有法术体系，而是先把普通法术的四阶段闭环做稳：

```text
开模 → 提纯 → 灌注 → 释放
```

## 2. 架构

```text
后端：Python + FastAPI + Pydantic
前端：React + TypeScript + Vite
数据：JSON 节点库 + JSON 示例
参考资料：Markdown 人工资料
```

核心文件：

```text
backend/app/models.py
backend/app/node_library.py
backend/app/graph_compiler.py
backend/app/routes.py

frontend/src/main.tsx
frontend/src/styles.css

data/nodes/mvp_nodes.json
data/examples/*.json
data/magic_have/*.md
```

## 3. 后端

后端提供两类接口。

MVP 接口：

```text
GET  /api/nodes
GET  /api/examples
POST /api/compile-graph
```

Legacy 接口：

```text
GET  /api/catalog
POST /api/compile
```

`graph_compiler.py` 负责：

- 四阶段完整性校验。
- 阶段重复校验。
- 空阶段校验。
- 未知节点校验。
- 节点阶段归属校验。
- 复合提纯匹配。
- 灌注输入依赖校验。
- 释放输入依赖校验。
- 风险聚合。
- 六维雷达。
- 法术卡输出。

## 4. 前端

前端是单页工作台。

当前页面结构：

```text
顶部：项目名、节点库版本、编译按钮
左侧：节点库、施法意图、施法者参数、示例载入
中间：开模、提纯、灌注、释放四阶段
左侧：可收起滑出节点抽屉
中间：四阶段构建区
底部：编译状态、法术名、简述、六维雷达
```

当前交互：

- 点击节点库节点，加入对应阶段。
- 阶段内上移、下移、删除节点。
- 载入四个示例。
- 修改施法意图和施法者参数。
- 调用 `/api/compile-graph` 编译。
- 展示失败、警告和高危结果。

## 5. 数据

运行时只读取结构化 JSON：

```text
data/nodes/mvp_nodes.json
data/examples/*.json
```

Markdown 资料只作为人工参考：

```text
data/magic_have/*.md
```

不要从 Markdown 自动生成运行时规则，除非后续另立需求。

## 6. 验收状态

已验证：

```text

前端 npm run build：通过
桌面 1440x900：四阶段完整显示，无右侧遮挡
移动 390x844：无水平溢出

```

已发现并修复：

- 后端重复阶段会被静默覆盖的问题。
- 前端 1440x900 下释放列被右侧检查器遮挡的问题。

## 7. 当前限制

- `partial` 仍是预留状态，触发语义需要后续细化。
- 阶段之间是固定顺序，不支持自由连线。
- 结界、祈愿、契约、附魔尚未进入运行时。
- 示例数量有限，当前只覆盖普通四阶段法术。
- 未实现项目保存、版本历史、权限和部署。

## 8. 下一步建议

优先级从高到低：

1. 细化 `partial` 状态。
2. 增加节点库版本字段和兼容策略。
3. 扩展示例覆盖失败、unsafe、复合、错阶段节点。
4. 增加前端端到端测试或截图回归。
5. 评估是否把阶段内有序列表升级为连接图。

结界、祈愿、契约、附魔应等普通四阶段稳定后再进入独立扩展。
