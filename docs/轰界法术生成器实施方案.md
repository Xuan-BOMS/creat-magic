# 轰界法术生成器实施方案

## 1. 定位

项目按“法术编译器”建设。系统根据节点链路判断法术能否成立，而不是把法术做成百科条目。

MVP 目标是完成普通法术四阶段闭环：

```text
开模 → 提纯 → 灌注 → 释放
```

## 2. MVP 取舍

第一版只做固定四阶段和阶段内有序节点列表。

暂不做：

- 自由图或 DAG。
- 跨阶段手动画边。
- 结界、祈愿、契约、附魔完整体系。
- 项目保存、版本历史、登录、部署。
- AI 自动命名或 AI 自动规则判定。

这样可以先验证核心产品假设：玩家能否通过节点顺序构造可执行法术，系统能否清楚说明成立与失败原因。

## 3. 后端结构

保留现有 legacy 目录式接口：

```text
GET  /api/catalog
POST /api/compile
```

新增 MVP 图编译接口：

```text
GET  /api/nodes
GET  /api/examples
POST /api/compile-graph
```

核心文件：

```text
backend/app/models.py
backend/app/node_library.py
backend/app/graph_compiler.py
backend/app/routes.py
data/nodes/mvp_nodes.json
data/examples/*.json
```

## 4. 编译流程

1. 读取结构化节点库。
2. 校验四个阶段是否存在。
3. 校验每个阶段是否至少有一个节点。
4. 校验节点是否存在、是否放在正确阶段。
5. 开模阶段输出模具。
6. 提纯阶段输出单元素或表内复合属性。
7. 灌注阶段消费模具和元素，输出灌注结果。
8. 释放阶段消费灌注结果，输出最终效果。
9. 聚合风险标签和评分偏置。
10. 输出状态、法术名、简述、阶段结果、问题定位、七维评分和法术卡。

## 5. 硬规则

- 状态枚举：`compiled`、`partial`、`failed`、`unsafe`。
- 缺少固定阶段：`failed`。
- 阶段为空：`failed`。
- 未知节点：`failed`。
- 节点放错阶段：`failed`。
- 灌注缺少模具或元素：`failed`。
- 释放缺少灌注结果：`failed`。
- 有高压、治理审查等高危标签：`unsafe`。

## 6. 前端工作台

主界面结构：

```text
顶部：项目名、节点库版本、编译按钮
左侧：节点库、施法意图、示例载入
中间：开模、提纯、灌注、释放四阶段容器
右侧：检查器、编译状态、法术卡、七维评分、问题定位
```

第一版交互：

- 点击节点库节点加入对应阶段。
- 在阶段内上移、下移、删除节点。
- 点击编译发送完整阶段构建。
- 编译失败时显示问题定位。
- 选中节点时在检查器显示摘要和标签。
