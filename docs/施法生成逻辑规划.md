# 轰界法术生成器规划

## 产品目标

本项目构建“法术编译器”，不是法术百科或元素技能树。

用户把节点放入施法阶段，系统先判断法术链路是否成立，再输出名称、简述、阶段结果、成立条件、代价、风险、失败原因和优化建议。

核心判断：

```text
魔法是理解框架。
法术是可执行流程的结果。
```

## MVP 范围

第一版只实现普通法术四阶段：

```text
开模 → 提纯 → 灌注 → 释放
```

阶段内部暂时使用有序节点列表，不做自由图/DAG。前端可以用箭头表现节点连接，但后端按列表顺序线性编译。

### 开模

目的：建立可承载提纯与灌注的模具。

第一批节点：

```text
球形、刃形、范围、线形、墙体
```

输出示例：

```text
球形弹体、刃形模具、范围场域、线形路径、墙体模具
```

### 提纯

目的：决定使用的元素或复合属性。

第一批节点：

```text
火、水、风、土、以太操作
```

复合只支持结构化表内组合，不做自由推导。

MVP 支持：

```text
火 + 风 + 水 → 雷电系法术
土 + 水 → 泥沼系法术
水 + 土 → 泥沼系法术
```

### 灌注

目的：把提纯结果注入开模结构。

第一批节点：

```text
标准灌注、压缩灌注、范围灌注、多重灌注
```

硬规则：

- 灌注必须消费开模结果。
- 灌注必须消费提纯结果。
- 缺少任意输入都不能编译成功。

### 释放

目的：使已经完成的法术结构产生效果。

第一批节点：

```text
投射释放、激发释放、扩散释放、流动释放、场域释放
```

硬规则：

- 释放必须基于灌注结果。
- 缺少灌注结果时，释放阶段失败。

## 数据设计

运行时规则使用结构化 JSON：

```text
data/nodes/mvp_nodes.json
data/examples/*.json
```

`data/magic_have/*.md` 只作为人工资料参考，不直接作为运行时规则库。

节点定义至少包含：

```text
id
stage
name
category
summary
outputs
tags
risk_tags
score_bias
```

节点实例必须区分：

```text
node_id      节点定义 ID
instance_id 画布中的节点实例 ID
```

## 编译 API

MVP 新接口：

```text
GET  /api/nodes
GET  /api/examples
POST /api/compile-graph
```

旧接口保留：

```text
GET  /api/catalog
POST /api/compile
```

`POST /api/compile-graph` 输入：

```json
{
  "intent": "远程伤害",
  "stages": [
    {"stage": "model", "nodes": []},
    {"stage": "purify", "nodes": []},
    {"stage": "infuse", "nodes": []},
    {"stage": "release", "nodes": []}
  ],
  "caster": {"focus": 65, "control": 60, "knowledge": 2},
  "context": {"environment": "训练场"}
}
```

输出：

```text
status: compiled | partial | failed | unsafe
spell_name
summary
stage_outcomes
issues
radar
spell_card
```

问题定位必须包含：

```text
rule_id
severity
stage
node_instance_id
message
suggestion
```

## 七维评分

```text
威力
稳定性
易学性
魔力效率
泛用性
学术价值
安全性
```

所有维度都是越高越好，避免雷达图误读。

## MVP 示例

```text
火球术：球形 → 火 → 标准灌注 → 投射释放
多重风刃：刃形 → 风 → 多重灌注 → 流动释放
泥沼术：范围 → 土 + 水 → 范围灌注 → 扩散释放
雷电术：线形 → 火 + 风 + 水 → 压缩灌注 → 激发释放
```

雷电术应输出 `unsafe`，因为它具备高压误伤和治理审查风险，但链路本身可形成结果。

## 第一阶段验收

- `/api/nodes` 返回节点库。
- `/api/examples` 返回四个示例。
- `/api/compile-graph` 能编译四个示例。
- 后端能拒绝缺阶段、空阶段、未知节点、错阶段节点、缺灌注输入、缺释放输入。
- 前端能添加、排序、删除节点并编译。
- 前端能展示阶段结果、问题定位、七维评分和法术卡。
