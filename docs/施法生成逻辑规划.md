# 轰界法术生成器规划

## 目标

本项目不做法术分类百科，而是构建一套从施法角度出发的生成逻辑：用户选择目的、介质、操作、载体、约束等节点，系统根据规则连接成可执行的法术链路，并输出成立条件、施法流程、代价、风险与可改进方向。

核心判断：

```text
法术不是元素名称，而是一次可执行流程。
魔法是理解框架，法术是流程结果。
```

因此系统应像“法术编译器”，而不是“技能树图鉴”。

## 实现方向选择

选择服务器 + 前端访问模式。

原因：

- 节点图编辑天然适合浏览器交互。
- 规则引擎、节点库、用户方案、版本历史适合集中存储。
- 后续可以多人访问、远程演示、权限控制和持续更新。
- 若未来仍需要离线版，可用 Docker、本地部署或 Tauri/Electron 包装 Web 版本。

不优先做 exe。exe 适合单机工具，但不适合长期维护节点库和规则版本。

## 产品形态

第一屏就是法术生成工作台。

主要区域：

- 左侧：节点库。
- 中央：节点图画布。
- 右侧：当前法术链路详情。
- 底部：编译结果、风险报告、失败原因、优化建议。

用户流程：

```text
选择施法目的
→ 选择介质或接口
→ 连接操作节点
→ 添加载体和约束
→ 点击编译
→ 得到法术流程、成立条件、代价和风险
```

## 核心模型

### 1. 法术链路

```text
意图 → 介质 → 开模 → 提纯 → 灌注 → 释放 → 结果 → 代价校验
```

特殊体系可以替换或包裹部分步骤，但不能绕开“成立条件”和“代价校验”。

例如祈愿：

```text
意图 → 请求语义 → 祈愿法阵 → 魔网链接 → 神之遗物返还 → 寄托物承载 → 结果 → 歧义与反噬校验
```

例如结界：

```text
意图 → 环境条件 → 诱因 → 转化 → 回填 → 循环闭合 → 子功能挂载 → 维护校验
```

### 2. 节点类型

#### 意图节点

定义用户想达成的目标。

示例：

- 伤害
- 防御
- 治疗
- 移动
- 侦查
- 封锁
- 强化
- 干扰
- 召唤
- 契约
- 改造
- 维持

#### 介质节点

定义使用哪类现象倾向。

```text
火：释放、升温、燃烧、扩散、耗氧、恐慌
水：流动、液态、湿度、溶解、卸力、净化
风：运动、气压、气流、切割、机动、扰动
土：结构、固化、密度、承载、构型、束缚
以太：泛用、无属性干涉、矢量、振动、搬运、感知
雷电：刺激、传导、电磁、神经调谐、屏障、光道
生命：生长、愈合、代谢、生态循环、血肉改造
灵魂：驱动、意识接口、附着、契约束、短窗干预
信念：情绪、叙事、神明构设、占卜诱导、巫术爆发
```

#### 流程节点

对应施法步骤和流程改写。

- 开模：建立边界、形状、容器。
- 提纯：提取目标现象倾向。
- 灌注：把介质填入结构。
- 释放：确定触发、落点、方向和稳定。
- 压缩：提高密度或效果集中度。
- 扩散：扩大覆盖范围。
- 延迟：拉长流程并积蓄效果。
- 序列：把条件触发写入施法行为。
- 多重：并行执行多个流程窗口。
- 附加：主系稳定输出，辅系催化放大。
- 复合：多介质相互干涉，形成新现象。
- 循环：把结果回填为下一轮起因。

#### 结构节点

定义法术最终形态。

- 弹体
- 刃
- 壁
- 场域
- 结界
- 附魔
- 卷轴
- 魔像
- 傀儡
- 召唤体
- 契约
- 诅咒
- 仪式
- 领域

#### 载体节点

定义施法依托。

- 手势
- 咏唱
- 法杖
- 魔法阵
- 符文
- 魔石
- 卷轴
- 魔道具
- 寄托物
- 身体器官
- 声音
- 图画
- 祭坛
- 使魔
- 魔网

#### 约束节点

定义系统必须检查的风险。

- 精神力消耗
- 注意力并发
- 被打断风险
- 环境成立条件
- 材料成本
- 载体耐受
- 目标权限
- 反噬
- 外溢
- 伦理风险
- 治理风险
- 禁术风险

## 连接规则

每条边都需要检查：

- 上游节点是否提供下游所需输入。
- 介质是否能被该操作处理。
- 载体是否能承受该输出。
- 目标是否具备施法权限或可操作窗口。
- 代价是否超过施法者能力。
- 结果是否引发治理风险。

示例规则：

```text
没有开模或等效结构时，弹体类法术不能编译。
没有释放节点时，主动攻击类法术只能停留在蓄势状态。
祈愿接口必须绑定代价和寄托物，否则标记为不可控。
常规法师不能直接对目标体内液体稳定施法，除非获得体内权限、规则系权限或特殊载体。
多重法术会提高注意力并发要求，不等同于连续释放。
延迟法术必须有维持方案，否则持续扣除精神力并提高失控概率。
结界类法术必须检查天时、地利、人和至少一类成立条件。
天灾类效果不以威力判定，而以不可控、试错成本和外溢后果判定。
```

## 编译流程

### 1. 解析意图

把用户目标转成效果标签。

```text
我要困住敌人 → 束缚、封锁、限制移动
我要保护队友 → 防御、遮蔽、卸力、持续维持
我要远距离探查 → 侦查、感知扩张、信息回传
```

### 2. 生成候选路径

系统根据效果标签找可用介质。

```text
束缚 → 土、泥沼、水、风压、契约、结界
防御 → 土、水、电磁、结界、附魔
侦查 → 风、以太、光道、魔眼、结界支流
```

### 3. 补齐流程节点

普通法术默认补齐四步。

```text
开模 → 提纯 → 灌注 → 释放
```

如果用户使用魔法阵、卷轴、魔道具，则部分步骤可被前置或外包，但仍要显示“由谁/什么承担”。

### 4. 注入技巧

允许添加：

- 序列
- 多重
- 延迟
- 附加
- 复合
- 结界循环
- 魔药/素材强化
- 祈愿接口

技巧不直接等于变强，而是改变成本、稳定性、触发方式和风险。

### 5. 校验与评分

输出四项分数：

- 可执行性
- 稳定性
- 代价可承受性
- 治理安全性

同时给出失败原因。

### 6. 输出法术卡

法术卡包含：

- 名称
- 施法目的
- 节点链路
- 施法步骤
- 成立条件
- 代价
- 风险
- 适用场景
- 失效场景
- 优化建议
- 禁术/天灾/授权标签

## 示例

### 火球术

```text
意图：远程伤害
介质：火
结构：球形弹体
流程：开模 → 提纯 → 灌注 → 释放
载体：手势 + 咏唱/法杖
风险：被打断、热场外溢、友军误伤、精神力沉没成本
结果：基础攻击法术，可教学、可变体、可扩容
```

### 多重风刃

```text
意图：多目标切割
介质：风
结构：刃
技巧：多重
流程：多个开模/提纯/灌注/释放窗口并行
代价：注意力并发高、稳定性低
适用：目标分散时比单个 AOE 更有效
```

### 侦查结界

```text
意图：长期侦查
介质：风/以太/光道
结构：人和结界
流程：环境诱因 → 信息采集 → 回填供能 → 子系统持续运行
代价：前期建设高、维护要求高
优势：建成后可降低实时精神力消耗
```

### 祈愿传送

```text
意图：移动到目标地点
接口：祈愿
要求：坐标、传送方式、目标状态、代价、寄托物
风险：坐标成立但状态失配、语义偏移、链接到错误遗物、时间线副作用
结论：可编译但默认高危，需要严格参数和授权标签
```

## 关键原则

- 先规则，后文案。
- 先判断能不能成立，再生成好听名字。
- 法术结果必须能追溯到节点链路。
- 高阶不自动更强，强弱取决于目的、场景、代价和可控度。
- 祈愿、时间、空间、记忆、心灵等高位接口默认高风险。
- 生成失败要比强行生成更有价值。
- AI 可用于润色法术卡，但不应替代规则引擎做世界观判定。
